Rebuild

compiler when absent, prepares external kernel headers, and builds the paired

The installed pair was built from the repository root with retained tools:
  RP1_TOOLCHAIN_DIR=/private/tmp/rp1-wifi-driver-build/aosp-gcc48 RP1_BUILD_DIR=/private/tmp/rp1-wifi-driver-build/kernel-build bash misc/rp1-wifi/build-driver.sh

Required flags and ABI
- -fno-pic -fno-pie must appear in CC itself, including feature probes. AOSP
  GCC otherwise creates unsupported GOT relocations and omits CC_HAVE_ASM_GOTO,
  shrinking struct module from the stock 0x178 bytes to 0x170.
- Host tools use Apple clang -arch x86_64 and -Wl,-no_pie, with the retained
  ELF header. NDK clang 18 is unsuitable for this unmodified kernel: the local
  register asm("sp") used by current_thread_info is miscompiled.
- Both modules are ARMv7 EABI5, version C509.p2-rp1fix8, with vermagic
  "3.14.35 SMP preempt mod_unload ARMv7 " and a 0x178 module structure.
- MLAN retains all 14 factory exports and 5 imports. The 252 sd8897 imports
  resolve against the paired module and 7416 cached device exports. No GOT
  relocations remain. CONFIG_MODVERSIONS=n; a full-kernel Module.symvers is
  not required for this build.
- The external sd8897 depends on mlan8897; the stock pair uses the older
  mlan8777 dependency name. Install and unload the matching pair together.
- patched/ contains the exact unstripped build outputs. SHA256SUMS records
  these modules, the source, installer, cumulative patch and test fixture.
  resume-fix.patch is regenerated against pristine C509.p2.

The worker rebuilds for address changes. Successful STA MAC changes queue the

Host checks pass under ASan/UBSan: the actual builder, packet matching, dynamic
IPv4/MAC, request ownership, failure cleanup and temporary negative controls.
The installer tests cover upgrades, interruption recovery and rollback.

Installed on the RP1, then independently unloaded/re-enabled Wi-Fi. Both fix8
modules loaded from /system/lib/modules and prepared the whitelist without a
manual MEF command. Boot and factory-module hashes were unchanged; /system
and its block device returned to read-only.

Online firmware-HS tests kept the driver-managed table enabled: own IPv4 and
client DHCP DF0/DF1 passed; unrelated broadcasts and other-client DHCP were
blocked in HS and received awake. Multicast had no awake delivery control and
was not counted as a pass. Cleanup left HS inactive, the original HS cache,
filter=Y and diagnostic=N. Real DHCP REQUEST/ACK and the existing 15:45 local
sync also passed. These USB checks do not measure CPU deep sleep or energy.
The separate battery test used the byte-identical temporary table; its scope
