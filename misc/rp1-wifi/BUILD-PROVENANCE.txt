The script downloads and SHA256-verifies that official toolchain into .build/aosp-gcc48 when absent, prepares headers in .build/kernel, and builds source/wlan_src. No global installation and no device access.

This permits host modpost to build on macOS. Host tools use Apple clang -arch x86_64 and -Wl,-no_pie, which avoids arm64 Mach-O text relocation failures in old file2alias.c. Sony kernel source stays read-only; only external O= output and copied driver generate build files.

Critical target flags:
-fno-pic -fno-pie MUST appear in the CC command itself, not only KCFLAGS.
AOSP GCC defaults to PIC: otherwise gcc-goto.sh fails, CC_HAVE_ASM_GOTO is omitted, and struct module wrongly shrinks from 0x178 to 0x170. PIC also creates GOT relocations unsupported by this kernel loader.
NDK clang18 is unsuitable without additional kernel header changes: local register asm("sp") used by current_thread_info is miscompiled. Do not deploy clang baseline artifacts.

Baseline static checks:
Both vermagic: 3.14.35 SMP preempt mod_unload ARMv7
Both .gnu.linkonce.this_module: 0x178 (stock matches)
14 MLAN exports, kernel imports, and 61 stock parameters match.
Stock sd8897 depends=mlan8777; external pair depends=mlan8897. Use actual /proc/modules names when unloading and load the new matching pair together.
Missing full-kernel Module.symvers is expected with CONFIG_MODVERSIONS=n; static imports were separately checked against stock and device __ksymtab.
No device operations are performed by the script.
